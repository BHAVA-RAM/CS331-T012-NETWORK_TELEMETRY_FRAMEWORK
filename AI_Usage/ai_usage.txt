The primary AI tool used throughout the project was ChatGPT. It was used as a technical assistant for understanding networking concepts, evaluating design decisions, generating initial implementation code and commands, debugging errors, explaining unfamiliar libraries and protocols, and preparing project documentation and presentation material.

ChatGPT was not used as a replacement for understanding the project requirements. The project requirements were first analyzed independently, after which ChatGPT was used to cross-check the interpretation and identify possible gaps or incorrect assumptions.

No other AI tool was used for the implementation. ChatGPT was the only AI assistant used for technical guidance, code generation, debugging, documentation, and presentation preparation.

Prompts / Types of Prompts Used

The interaction with ChatGPT was iterative rather than based on a single prompt. The major categories of prompts included:

1. Requirement and architecture understanding

Initial prompts focused on understanding the project statement and converting the requirements into a possible system architecture. Examples included prompts asking ChatGPT to:

explain the project requirements in simple terms;
identify what components would be needed for collection, transport, storage, visualization, and alerting;
determine how technologies such as SNMP, gRPC, REST APIs, PostgreSQL, Grafana, Docker, and OpenTelemetry could fit into the architecture;
verify whether the proposed architecture actually satisfied the project statement.

The purpose was to validate the architecture before implementation.

2. Learning SNMP and network telemetry concepts

Prompts were used to learn the concepts required before implementation, including:

What is SNMP?
What are SNMP managers and agents?
What are MIBs and OIDs?
How are SNMP OIDs structured?
Which OIDs provide interface traffic, interface speed, and interface status?
How do snmpget and snmpwalk work?
Why are interface traffic values represented as cumulative counters?
How can bandwidth be calculated from two consecutive counter readings?
What is interface utilization?
What is the difference between SNMPv2c and SNMPv3?

These prompts were used before implementation so that the generated commands and code could be understood rather than copied blindly.

3. Docker and simulated network devices

Because a physical router or switch was not available for development, prompts were used to determine how to create a realistic laboratory environment using Docker.

Examples included asking:

how to create an isolated Docker container that can act as an SNMP-enabled network device;
what Docker command should be used;
what each part of a Docker command means;
how Docker networks allow containers to communicate;
how container names can be used instead of container IP addresses;
how a second independent SNMP device can be created.

The generated Docker commands were then executed and tested locally.

4. Collector implementation

Prompts were used to design and understand the Python collector.

Examples included asking ChatGPT to:

create a Python collector using PySNMP;
retrieve interface counters from the SNMP agent;
retrieve interface speed;
calculate bandwidth from cumulative counters;
calculate interface utilization;
measure latency using ping;
poll devices at regular intervals;
support multiple devices;
handle SNMP counter resets or decreases;
explain each function and imported library.

The collector code generated by ChatGPT was then tested against the simulated SNMP containers.

5. gRPC and Protocol Buffers

Since gRPC and Protocol Buffers were unfamiliar technologies at the beginning, prompts were used to understand them before integrating them.

Examples included asking:

what gRPC is and why it is useful between collector and backend;
what Protocol Buffers are;
how to define a .proto file;
how to generate telemetry_pb2.py and telemetry_pb2_grpc.py;
how the collector calls the backend;
how the backend implements the generated service;
how Docker containers communicate through the gRPC port.

ChatGPT generated an initial gRPC demonstration and then the project-specific telemetry.proto, collector integration, and backend service.

6. Backend, database, and REST API

Prompts were then used to build the central backend and storage layer.

ChatGPT was asked to:

create a gRPC backend;
store received telemetry in PostgreSQL;
design the telemetry table;
explain SQL queries and database connections;
create a FastAPI REST API;
provide an endpoint to retrieve historical telemetry;
provide an endpoint for CSV export;
explain the difference between gRPC communication and REST communication.

The resulting design was:

Collector
    ↓ gRPC
Backend
    ↓
PostgreSQL
    ↓
FastAPI REST API

7. Grafana dashboards and alerting

Prompts were used to understand how Grafana could consume the PostgreSQL data and satisfy the visualization and alerting requirements.

They included requests to:

connect Grafana to PostgreSQL;
write SQL queries for incoming utilization, outgoing utilization, and latency;
use device_name as a dashboard variable;
create a device-selection dropdown;
configure Grafana alert rules;
understand reducers such as Last;
understand pending periods, evaluation intervals, and firing periods;
configure thresholds for utilization and latency.

When a Grafana query initially produced a PostgreSQL timestamp error, ChatGPT was used to diagnose the mismatch between the BIGINT Unix timestamp stored in the database and Grafana's time filtering mechanism. The query was subsequently corrected to use Unix-epoch-aware time macros. while working with grafana chatGPT can't help because of updated version of grafana so i had implemented almost grafana part using google for how to set alerts,dashboard creation,notification policies,folders..

8. Debugging and verification

ChatGPT was also used after implementation whenever an error occurred.

For example, the development process included diagnosing:

SNMP OID queries returning missing objects;
Docker network connectivity;
Python imports after reorganizing files;
gRPC module placement;
PostgreSQL connection behavior inside Docker;
FastAPI database hostname configuration;
Grafana PostgreSQL time-filter errors.

The debugging process was interactive: the observed error/output was provided to ChatGPT, the cause was discussed, a correction was proposed, and the modified implementation was tested again.

9. Documentation and presentation

After the implementation was complete, ChatGPT was used to structure:

the project report;
repository README documentation;
the 5-slide presentation according to the TA's required structure.

The generated documentation was reviewed and edited to match the actual project rather than being submitted unchanged.
